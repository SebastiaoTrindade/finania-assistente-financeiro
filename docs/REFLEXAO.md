# Reflexão sobre o processo

O principal aprendizado deste desafio foi perceber que Vibe Coding não significa apenas pedir para uma IA “criar um aplicativo”. O resultado melhora quando o problema é definido antes da tecnologia, o escopo é reduzido e cada requisito tem uma razão clara para existir.

Durante a concepção do FinanIA, a ideia inicial poderia facilmente crescer para integrações bancárias, autenticação, banco de dados, investimentos e automações. O refinamento do prompt ajudou a separar o que demonstrava a proposta de valor do que apenas aumentaria a complexidade. O MVP passou a se concentrar em quatro pontos: registrar dados, entender o mês, estabelecer uma meta e conversar sobre os próprios números.

Outro aprendizado foi tratar a IA como parceira de desenvolvimento e não como substituta da avaliação humana. Foi necessário revisar decisões de produto, limitar o que o agente poderia afirmar e impedir que informações financeiras fossem inventadas. Também foi importante pensar no custo: para uma demonstração acadêmica, o comportamento conversacional pode ser validado com regras locais antes de conectar uma API paga.

O processo mostrou que bons prompts funcionam como uma especificação: contexto, problema, público, escopo, regras, restrições e critérios visuais reduzem ambiguidades. A IA acelera a construção, mas a qualidade final continua dependendo das decisões, testes e refinamentos feitos pelo desenvolvedor.
